# JSON Schemas for NIAID records

Generated by [`../build_nde_jsonschemas.py`](../build_nde_jsonschemas.py) from
[`../schemas/NDE_schema.jsonld`](../schemas/NDE_schema.jsonld) and
[`../niaidExamples/`](../niaidExamples/). Draft-07, with bare property names as the
portal publishes them (`name`, not `schema:name`). Regenerate rather than edit.

| Path | What it is |
|---|---|
| `asSpecified/<Class>.schema.json` | What NIAID says a record should be, for all 9 classes: the `$validation` of each class node, with `owl:cardinality` made enforceable |
| `asPublished/Dataset.schema.json` | What the portal's `Dataset` records are: the as-specified schema relaxed against the 140 example records |
| `relaxations.json` | Every relaxation with the records that needed it, undeclared names, and the cardinality changes |

Only `Dataset` has an as-published form, because the examples are all Datasets.

## Results

`Dataset` records validated with formats checked, 2026-11-04:

| Records | As specified | As published |
|---|---|---|
| The 140 examples (the schema was fitted to these) | 0 pass | 140 pass |
| 560 others from 48 sources (not used to build it) | 0 pass | 537 pass |

The 23 failures on the 560 are mainly NDEx records with no `description` (12 of 12
sampled), then `type` and `format` rules in EMPIAR, MicrobiomeDB, VDJServer,
PlasmoDB and ToxoDB. They were not relaxed, so that the 560 stay a fair test.

## Reading these

- The relaxations are evidence about these records, not a specification. Some
  may be portal or source problems that should stay failures. The largest are
  `includedInDataCatalog` as an array (NIAID's schema accepts arrays but annotates
  it `owl:cardinality: one`), `catalog.url`, `citation.name`, and `dateModified`
  and `identifier` on distributions and grants.
- `distribution`, `measurementTechnique`, `funding`, `date` and `author` are no
  longer required at the top level; they move to `recommended`.
- Unknown properties are allowed, as in NIAID's schema. `undeclaredNested` in
  `relaxations.json` lists names the records use and the schema nowhere declares,
  such as the annotation fields `fromGPT` and `fromPMID`.
- `owl:cardinality`, `recommended`, `optional`, `vocabulary` and `strict` are kept
  as NIAID wrote them, and JSON Schema validators ignore them. `vocabulary` names
  the ontologies a term should come from, which is not checked here.
- `format` checks depend on the validator: `uri` needs the `rfc3987` package in
  Python's `jsonschema`, and without it those checks are skipped.
